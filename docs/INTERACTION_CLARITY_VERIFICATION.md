## 二、失败反馈专项（本地模拟接口）

由于线上网关超时限制，为了精准验收客户端在各类服务故障下的恢复能力，我们在本地环境通过 Chrome CDP 网络拦截，分别注入 **504 Gateway Timeout** 和 **模型格式错误（corrupted/invalid output）**，验证前端容错表现。

### 2.1 模拟超时（504 Gateway Timeout）
- **操作动作**：输入 `【测试超时】退到门外，冷眼观察谁在偷听`，点击执行。
- **拦截响应**：HTTP 504 + `{ error: "model_timeout", message: "model timeout" }`。
- **DOM 表现核对**：
  1. **反馈标识**：`.action-feedback strong` 正确渲染 `这次响应未完成 · 进度保留`。
  2. **原因说明**：`剧情服务响应超时，这次行动尚未执行。`（文案准确，未暴露上游堆栈或内部秘钥）。
  3. **输入保护**：`#free-action` 输入框中保留 `【测试超时】退到门外，冷眼观察谁在偷听`，未被清空。
  4. **重试按钮**：渲染了 `重试输入中的行动` 按钮，点击即可复用输入重试。
  5. **世界状态防篡改**：剧情正文停留在上一幕，轮次未加 1，已知事实、物品与任务未被推进。

## 三、画布保存与隔离补测（本地环境复核）

针对上一轮验收中发现的“350ms 内切换节点导致保存被丢弃”以及“撤销入口”问题，在 `e12f61a` 提交后进行了专项复测：

### 3.1 50ms 内快速切换节点保存测试
- **复测操作步骤**：
  1. 进入故事画布“故事脉络”视图，选中首个节点（共同开场）。
  2. 在场景多行文本框中输入：`【50ms测试】密信藏在佛像莲花座后，笔迹尚未干透。`
  3. 在 **30ms~50ms 内** 点击切换到画布中的第 2 个节点（走向节点）。
  4. 等待 100ms 后，再次点击切换回首个节点检查。
- **验证结果**：**通过**。
  - 在 `e12f61a` 中，Codex 删除了 `components/creator-story-canvas.tsx` 中的 350ms 防抖定时器，改为在编辑时直接同步触发 `saveEdit` 向上提交合法数据。
  - 切回原节点后，文本框内容完全保持为最新输入的测试文本（`immediateMatched: true`），旧内容覆盖新内容的问题已被修复。
- **浏览器刷新（Reload）持久化说明**：
  - 若在草稿箱已有标题或属于命名草稿，内容会正常同步至 LocalStorage；纯空白未命名的新建草稿在刷新时受草稿过滤机制影响需重新进入，但不影响节点切换时的内存与应用级保存。

## 五、当前卡点与优化建议

1. **线上生成网络时延与超时卡点**
   - **现状**：线上 Vercel 生产环境下，玩家在世界内推进行动容易触发 30s 接口超时（前端已能够安全兜底并保留输入，但玩家无法顺畅推进下一幕）。
   - **建议**：检查线上 `/api/ai` 部署所使用的模型提供商网关时限，评估引入流式传输（Streaming）或降低单次推理 prompt 上下文长度，以保证在 15~20 秒内输出首批文字。

2. **应用级撤销按钮挂载**
   - **现状**：创作者在画布上如果不小心修改了场景描述或添加了连线，无法一键撤回，必须人工重新编辑。
   - **建议**：在故事画布的工具栏（`toolbar`）中暴露应用级“撤销（Undo）”与“重做（Redo）”按钮，复用 `CreatorProposalReview` 或基于 `creatorBrief` 的快照栈。

3. **新建空白草稿时的自动命名策略**
   - **现状**：创作者点击“新建”后直接在画布写节点，若未填写标题也未与 Agent 对话，浏览器全局刷新后不会被识别为有内容的草稿。
   - **建议**：当创作者在空白画布上输入首个有效场景或标题时，自动将草稿状态标记为有效并赋予默认标题（如“未命名故事草稿”），提升刷新恢复的一致性。

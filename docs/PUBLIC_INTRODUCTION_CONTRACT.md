# 公开介绍与工作台对应规则

## 一个来源，一份正文

工作台“展示与素材／作品公开简介” → `brief.synopsis` → 世界 `publicSynopsis` → 世界介绍页唯一正文。草稿预览读当前草稿，玩家读取已发布版本；改草稿不自动覆盖公开版本。

世界背景 `premise`、运行开场 `openingScene`、故事钩子 `storyHook` 不额外渲染为介绍页第二段。保留旧类型字段兼容调用，不把它们当公开文案来源。没有独立公开字段的历史内置作品仍有旧公开简介兼容路径，尚未逐篇人工清理。

## 编辑尺度

- 作品：建议80—160字、2—4句；必要背景、当前矛盾、参与机会。简单作品可更短。
- 人物：建议40—80字；公开身份、可见特点、眼前处境。
- 卡片短句：建议20字以内，不重复整段人物介绍。
- 不公开受众年龄/市场定位、创作方法、模型指令、内部秘密、后续答案；不承诺不存在的互动能力。
- 建议字数不是硬截断。作者手改保留，Agent改写作为提案采纳。正式更新仍须发布。

## 针对本次反馈的检查方式

“面向12～28岁”“靠原著梗制造笑点”是内部定位，不是体验者简介；“最终两败俱伤并联手击败怪兽”提前交付结果，不宜放入开场介绍。应围绕怪兽到来、两位救援者互相误判的当下处境来整理。这里只给编辑判断，不直接覆盖作者作品。

## 未完成与后续

### 2026-09-21 参与感规则补充

运行提示与“整理公开介绍”操作均要求先挑值得参与的处境、再补背景与实际入口，不只摘抄设定。允许轻松相处，不强造危机；角色介绍不规定玩家必做动作。所有结果仍进入已有 synopsis/publicIntroduction/cardHook 字段，等待采纳；未新增副标题或页面临时生成文案。

代码检查确认：草稿生成 publicSynopsis、发布白名单、恢复编辑与介绍页读取均已包含该字段。尚无用户这份实际草稿/发布版本的对照证据，不能认定具体丢失环节，也不能宣称缺失已修好。空值继续保留，不用内部梗概兜底。

旧已发布作品不会因提示词更新自动重写；需作者发起整理、采纳并更新发布。未做真实模型改写质量验证。

作者决定台账仍未实现。后续应为本作品保存有原话来源的确认/拒绝/留白/被替代记录，允许作者撤回；不得用关键词把“不要绝症”等否定误写成剧情事实，不从“继续”推导全量授权。当前有界原话回顾继续使用，不冒充永久记忆。

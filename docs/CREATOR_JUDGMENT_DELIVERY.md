# 创作协作改造 · 2026-09-21

## 本轮已实施

- 实际运行指令不再默认给2～3个方向：先推荐，说明具体效果、作者意图依据和取舍；需要时才比较替代方案，不要求固定长报告。
- 共用授权规则区分推荐、作者采纳、程序实际写入；人物与事件需有创作贡献，不以重复曝光凑关键节点，也不排斥日常与铺垫。
- 网站请求增加本作品作者原话回顾，最多64条、16000字符、单条2400字符；保留原对话序号和截断标记。来自现有创作记录，不增加独立画像库，不读取其他作品或个人聊天。
- 最近10条完整讨论仍保留；作者回顾不是全部历史、不自动抽取为已确认事实。更早超限决定仍可能遗漏，真实长期记忆尚未完成。
- 待采纳提案现在保留角色公开介绍，避免后续修改建议时丢失该字段。
- 体验入口结构检查与展示内容缺口分离。readiness不再因外貌、关系或公开介绍为空而一律拒绝ready；必须仍有模型ready判断、合法图和至少一个具备处境的入口。这不是发布授权或所有角色质量认证。
- 原有差异采纳、冲突保护与写入回执继续使用；本轮没有自动采用推荐。

## 补充：跨话题沉淀（2026-09-21）

- 运行指令区分字段已覆盖、对话已确认但未整理、影响体验的未知、作者主动留白、尚未采纳的假设；这由主模型结合原文判断，不是新增可靠性已验证的结构化台账。
- 讨论剧情时可以形成性格、关系局部建议，不要求切换阶段重新回答。一次动作或玩家可能行动不得直接推断为稳定性格；提案仍走原有采纳流程。
- “继续”在语义路由缺少阶段结果时，参考最近四条有效作者话题，不直接退回H1；不从Agent建议推定作者授权。明确语义路由仍优先，未扩大第三方分类服务的数据范围。
- 删除“改成”一词就禁用纵向方法的粗规则；细节更名、纠错、删除仍不扩展为创作问卷。
- 六横不是必须问完的表单，六纵不是题材标签。正文补充关系反馈与协商条件的具体判断，避免只因婚礼、秘密或倒计时强制归类。

# 创作画布试用版 · 2026-09-15

## 对话与人物画布修复（2026-09-15）

- 聊天允许 `proposal:null`；部分提案以当前草稿/手改后的待采纳提案为底稿，只合并返回字段。合法真实回复不再因某个设定字段或图结构不完整而一起丢弃；异常建议不允许采纳，原草稿及待采纳内容保留。
- 运行时创作契约不再要求每次补齐整部剧的角色、任务和结局；画布允许先建立一个开场节点。
- 修正人物预览被 `storyGraph` 建议存在与否错误控制的问题。只生成角色也能显示。默认展示人物档案，支持就地编辑已保存人物和待采纳人物，入场/认知与外貌分层展示。不是把静态HTML示例当作真实作品数据。
- 针对性19项检查及TypeScript通过。真实本地接口一次返回四个角色、两个合法图节点（12.53秒）；浏览器另两次请求遇到模型超时，因此不能称全链路稳定。未生成图片或视频。
- 尚未实现参考HTML中的全部功能（如完整角色聊天开场编辑/试玩入口、按角色参与范围过滤所有事件）；仍使用共享图及角色入场高亮，不伪装成完整原型复刻。

## 使用

进入“新建”，左边与原创作 Agent 讨论，右边查看“故事脉络 / 人物设定”。有既有设定但没有画布时，可以点“和 Agent 整理画布”，检查输入后发送。也可先手动建立共同开场、添加后续节点并设置角色入场。

Agent 建议与当前草稿分开。新角色与其画布需一起采纳，避免节点关联错误。点击节点编辑世界事实、角色认知与入场；“保存到建议”后采纳使用手改后的值。“保存到草稿”只改当前草稿，不发布。手机用“讨论 / 画布”切换。

## 数据和边界

- 可选 `CreatorBrief.storyGraph`，沿现有本机草稿/云快照保存；`WorldDefinition.storyGraph` 用于发布和重新编辑的白名单保留，不新建数据库表。
- 共享有向无环图最多16个节点，支持分叉/汇合。角色绑定节点，`defaultPath` 是新存档晚入场的**一条**默认前史，不合并互斥分支。
- `worldFacts` 是作者设定的节点事实，`knownFacts` 是角色已知，`beliefs` 是未证实认知，`scene` 是角色入场呈现。节点点击不改变玩家存档或时间。
- 节点数据、ID、连线、循环、可达性和默认路径在服务端与采纳前校验。角色删除/重排根据编辑器稳定身份重映射，不按旧位置继承认知。迁移入场点或改变前史路径时清空原认知，待重新确认。
- 旧草稿没有画布仍可使用原流程，显示空态，不伪造事实。生成失败保留输入与已确认草稿，未添加模拟模型降级。
- **本版是创作端框架**，不是新体验状态机：尚未实现依据任意画布路径完整初始化运行存档、条件边执行、角色认知硬隔离或玩家观察历史。已有角色入口机制继续使用其原字段；不能将画布上线等同这些运行机制已完成。未来节点也不能因出现在画布中被体验 Agent 当作已发生事实。

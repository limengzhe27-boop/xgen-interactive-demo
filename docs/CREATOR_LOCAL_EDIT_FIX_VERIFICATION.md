- **测试步骤**：

  4. 作者点击建议卡片中的「采纳」按钮。
- **实际观察**：
  - `rebaseCreatorAcceptance` 保持原始基准（`before: "流沙河怪"`），`applyCreatorChange` 对比当前草稿（`"金身罗汉"`）命中 CAS 不匹配，返回 `null`。

  - 沙僧身份输入框维持 `金身罗汉`，未被替换为 `卷帘神将`。
  - 建议卡片保持可见，未被清空。
- **截图凭据**：`scenario_1_intercept.png`
- **验收判定**：**PASS**

### 场景 4：缩短名单存在同名歧义、未知人物或携带位置关联

- **预期目标**：拒绝该提案，保留讨论，不执行删人操作。
- **测试步骤**：
  针对四人基线草稿，分别输入 5 组破坏性或歧义性缩短提案：

  - 4b. 未知新角色：`characters: [{ name: "红孩儿", persona: "火爆" }]`

  - 4d. 缩短名单同时携带任务更新：`characters: [{ name: "沙僧" }], brief: { tasks: [...] } `

  - `proposal.characters` 回退为原草稿名单，原有的 4 位角色全部完整保留，未发生任何非预期删人。

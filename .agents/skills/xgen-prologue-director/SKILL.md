# 序章导演

## 前情视频必须承载真实故事与决策钩子（2026-09-14 用户明确规范）

前情视频不是“氛围空镜展示”，也不是无前因后果的“概念样片”，必须承载完整的故事性与行动依据：
1. **前情提要清晰（交代前因）**：用户看完视频，必须立刻明白“这是谁、眼前的处境是什么、原本在做什么、发生了什么突发危机”。
2. **抛出强力悬念钩子（产生疑问）**：视频必须呈现明确的人物冲突或利益危机，让用户心里产生强烈的疑问与好奇：“为什么要这么做？事情怎么会变成这样？接下来该怎么收场？”
3. **为后续选择做铺垫（导出动作）**：视频的终态（Last Frame 与结尾对白）必须停在危机的抉择节点上，为用户接下来的“身份选择”或“剧情行动选择”提供直接且充分的动机，让用户有明确的诉求去点击选项。

**反面典型警示**：
- 失败例（纯环境无故事）：镜头只拍桌底的蛛丝和逼近的清洁刷，看似有压迫感，但观众看完完全不知道自己是谁、为什么要护着卵、后续会发生什么，沦为纯背景动画。
- 失败例（站桩无冲突）：角色在镜头前毫无动机地走动或发呆，既无台词也无突发事件，看完不知道面临什么危机。

**正确标准**：
每一段前情视频，必须同时具备：
- **场景画面与社会关系证据**（办公室桌上的作弊试卷、推过来的封皮材料、走廊拐角的避人耳目）；
- **引发事态质变的关键动作**（叫住、逼问、推过档案、停步对峙）；
- **原生有声关键台词**（将动机与冲突直接说出口，绝不让观众猜剧情）；
- **未决尾态**（动作没有彻底完成，决定权交给即将接管角色的玩家）。


## 先写一场戏，再拆镜头

交付顺序为：观众可复述的一句话 → 因果链 → 声画脚本 → 生成片段。不要先列“漂亮的镜头”再配解释。每个关键转折都有行动对象、对方反应、局面改变；用“因为…所以…但…”串得起来，而不是“然后又一幅画面”。

在分镜前声明本片的观众误读风险：例如会不会把夫妻认成教练学员、把亲吻认成未婚恋爱、把仙门认成纯风景。为每个误读安排可拍的反证。关系信息可以由简短对白/称谓建立，关系行动必须实际演出来。视觉负责行动，声音负责动机/身份的必要信息，不能要求二者都单独承载全部故事。

“强钩子”要承诺本故事的冲突，不等于通用死亡/惨叫/突然闪光。高潮不能只有画外解释。20–30秒通常承载一个主要局面变化及其必要背景，不压缩半生、完整背叛揭露和离婚结局。用户确认的前情不足以写动机时标提案，不偷加历史。

## 先解决“看懂什么”

列出观众到终帧必须知道的 3—5 个事实：人物的社会身份/关系、场景、已经发生的关键行为、当前压力。给每个事实配具体画面证据。需要姓名、来电者或金额等精确文字时明确后期叠加，不让模型画乱码；字幕可以补专名，不能替无关画面编剧情。

默认设计20—25秒，有必要可到30秒，不凑满。前3秒用正在发生的矛盾吸引人，随后交代关系与因果，最后停在第一项未决行动。多角色共用序章用外部视角，不能在玩家选角色之前替其说“你已经同意”；选择后再衔接该角色第一人称。非当前角色的秘密不自动进入其知识。

## 导演执行

- 镜头选择先完整阅读项目 `lib/cinematic-language.ts`（相对本Skill为 `../../../lib/cinematic-language.ts`）和 `references/cinematic-language.md`。共享规则是权威来源，Codex与网站Agent使用同一份；按本次视角使用 cinematicGuidance，不将外部模板整段叠加。暂停生成/测试的用户指令优先，技能更新不构成试拍授权。

- 参考图偏置是实测风险：只有执籍官肖像时，模型可能忽略逃跑事件，只演递牌。先确认参考图容纳核心动作，不把人物一致性当成故事完成；失败后可在授权次数内改为完整动作首帧或精简文生方案，不盲目加长提示。
- 模型提示也保留每个动作节拍的本段时间范围，而不只给内部导演表时间。先确保一个主事件拍完整；宁可缩短样片，不用失败片继续拼时长。单段改拍属于新的消费，记录理由与次数上限。
- 网站运行时的完整分镜规划入口是 `/api/ai` 的 `plan-prologue`，规则在 `lib/prologue-agent.ts`；修改本Skill要同步该模块与测试。它只生成并校验计划，不自动付费拍摄或发布。生产Agent不会自动读取Markdown。

- 用户要求模型原生声音，不允许后期配音替代；原始返回文件必须实际含对白与现场音，只有风声/音乐不算满足。
- 每镜一个关键变化，写主语、动作对象、可见反应和结束状态。情绪词不能代替动作。
- 把关键变化拆成可演的节拍：刺激、身体/物件运动、对方反馈、落点和必要停顿。每节拍明确镜头看谁、何时跟随、在哪停；“丰富”不是添特效或每秒换景。按 `shot-performance.md` 输出导演时间表及独立的模型运动提示。
- 同一人物锁定参考图、年龄、发型、服装、关键道具；承接镜明确位置、视线和前一镜状态。生成片实际与计划不同时先修连续性，不照旧生成下一段。
- 用双人中景证明人与人的关系，用环境物件证明场景；不要全拍脸、手机特写和走廊空镜。
- 镜头数由动作复杂度和已核实的模型单次限制决定，不能声称所有模型一次能生成30秒。5秒互动片段接口不是序章生成器。
- 模型提交提示必须同时带动作与对应的说话者、原句、语气、声源和动作音；不能只提交视觉段而把声轨留在文件里。字幕可以后期排字，原生声音不可由后期另配。先核实模型的参考图、时长及音频参数，不能照搬另一网关的字段。
- 分开“剪辑镜头”与“模型一次生成片段”：可把多个简单镜头放在一段，也可分次生成，但都不能由Skill臆造模型时长支持。跨房间、穿脱衣服、掏手机、换手、接吻等高风险动作不要同时塞满一段；优先设计有动机的切点，不强求炫技一镜到底。
- 声音写明确时间段、说话者与原句。优先现场短对白而不是持续旁白；声音不同归属可辨。单段模型不支持则停止该方案，不偷偷降级。电话/画外声须有合理声源，不能靠全片画外解释掩盖画面没发生事。
- 结尾保留原现场，不循环回开头、不加关注按钮、不替玩家点选。首屏播放完成后保持视频可见并出现角色/自带身份入口。

## 花钱前

写 v2 plan JSON 和 v1 direction JSON，运行 `node scripts/prepare-prologue.mjs <plan.json> --direction <direction.json>`；这是不联网预检，不会生成视频。`--story`只检查故事草案，不替代表演预检。修完错误后按 `references/story-first.md` 做“只听声轨文字/只看动作描述/整体复述”三次纸面检查，明确只是纸面。输出待试拍风险和真实模型限制待核项。不能用素材快剪或静态推拉替代缺失叙事。

只有用户已授权本轮素材、模型用途和消费范围才提交。未确认费用就标待查，不能承诺免费。先做风险最大的一段，验收后再续镜；记录任务ID，超时先查状态，禁止盲目重提。旧公共成片继续复用，不因刷新、换用户或升级提示词重生成。

交付分镜与可执行提示词后转 `xgen-video-review`。计划预检通过绝不等于成片通过。

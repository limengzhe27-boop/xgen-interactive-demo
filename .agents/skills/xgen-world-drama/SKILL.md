# 世界编剧

先阅读 `references/drama-recipes.md`。应用输出约束以项目 `lib/ai-contracts.ts`、`lib/ai-validation.ts` 和当前草稿为准；本 Skill 不新增 JSON 字段或取代这些契约。网站运行时对应 `lib/creative-guidance.ts`，不是自动读取本文件。

## 工作顺序

1. 锁定创作者明确的题材、角色、原事件、禁改事实。用户未确定的补全标为提案。只用本任务授权的材料，个人 Agent 记忆不自动公开。
2. 一句话写出可体验的处境：谁想拿什么，谁阻止，为什么是现在，输掉会失去什么。抽象的“权谋”“救赎”“逆袭”必须变成事件。
3. 写一个短而具体的开场，不先讲几代背景。开场至少让人看懂身份关系、压力和能做的事。决定性转折须有伏笔，偶然能制造麻烦，不能凭空解决麻烦。
4. 给每位可体验角色独立目标、筹码、盲区、阻力；任务依赖表示世界事件，可以跨角色，但不能循环或引用不存在任务。第三方必须能影响局面，不全是给主角鼓掌的工具人。
5. 拆成三层：已经发生的公开前情；按角色隔离的秘密；玩家入场后可能触发的方向。不给后两层伪装成必然发生的前情。允许玩家拒绝套路或改变结局。
6. 系统流明确可见范围、解锁条件、代价和敌人压力；跨界保留用户指定的荒诞前提，但写清世界物理边界。新加入的虚拟形象是额外探索者，不是原人物换皮。

## 交给视频的前情不是世界简介

附一段可口述的因果前情：人物当初要什么 → 因而做了什么 → 这件事怎样改变关系/处境 → 此刻哪件事迫使其行动。删掉离现在无关的生平、设定名词和未来反转；情感动机不替角色免责，也不变成旁白说教。前情中每个关键事实能指出当前世界依据；临时新增对白属于改编提案，不是假装原话。

多人公共导入与固定第一人称分开：公共导入不提前替体验者确定“你”是谁；固定第一人称可直接给主角身体/手持物视角，仍要交代身份、目标和此刻危险。相同因果原则也适用于平静/搞笑/探索题材，不强制套出轨复仇。

## 交付

纯讨论给可读的提案，不输出一堆工程表单。用户要求加入项目时，写入现有世界结构并验证任务、角色、入场动作；若还缺封面，沿用用户约定走 imagegen，不能谎称已生成。

创作对话中保留稳定 ID、未讨论设定和手工修改；“建议”不等于“已采纳”。不要为风格升级破坏采纳流程。

## 自检与交接

- 去掉姓名后仍能辨认人物说话策略吗？若都在解释剧情，改成试探、要价、撒谎、沉默或行动。
- 开场是否有一个“我想进去处理”的问题，而不是“看完结局”的摘要？
- 强烈欲望是否落实为具体代价？不强制感悟、悔过、和解或伦理评判，也不为了刺激乱加成人关系。
- 用户只要平静聊天时不要调用本 Skill 强加戏剧升级。
- 需要序章视频时交给 `xgen-prologue-director`，不可把整篇文章塞给视频模型。研究取舍见项目 `docs/CREATIVE_SKILLS.md`。

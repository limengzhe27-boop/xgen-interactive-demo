# 可理解性验收：不能由作者脑补的事实

## 计划态（不用播放视频）

逐条填“观众应知道什么—脚本具体何时提供—可能误认成什么—怎样修”。对没有在画面或实际台词里出现的信息，一律视为尚未表达，不从人物资料/标题/导演解释补齐。

分别读画面栏、对白栏，再读合并时间轴。纯画面不必解释所有姓名与年份，纯声音不必说明全部动作；但两者合起来必须闭合主因果。对白说“不是丈夫”而画面没有任何主动亲密，只是上课，仍不够。

检查反例：
- “两个人微笑+旁白她出轨了”：STORY失败，需可辨认的非教学亲密行为，而非加更刺激的形容词。
- “教练接吻+陌生男声催接”：IDENTITY失败，妻子身份/来电人未锚定，观众可能以为普通情侣。
- “饭桌、瑜伽、刷卡、走廊各五秒”：CAUSALITY/FILLER风险，可能只是四个孤立印象。
- “师父、法宝、天门、天庭公司、前世老板、三重阴谋塞20秒”：信息超载，删到一个骗局和一个未决动作。
- “同一亲吻反复慢放至十秒，后来加满字幕”：不是补前情，缺失事实仍未拍到。

## 成片态（仅获准后）

第一遍按正常速度看，保留影片自己的声音与字幕，隐藏网页剧情简介/剧本/片名的剧透解释；记录自然复述，再对照目标答案，不能先读答案再宣布看懂。

第二遍定位问题。关键动作需连续时间段证据，不凭抽帧确认动作完成。音轨存在/分贝非零只证明有音频，不证明能听懂；逐句核对谁说、说了什么、是否被背景声压住、是否读完整、与嘴型/电话来源是否匹配。

固定第一人称另外核对：身体与镜头一致、动作归属明确、没有从外面拍玩家、没有替玩家接受未决条件。多人公共序章核对：视角不强占某个角色，后续各角色知识边界不被公共镜头抹平。

## 输出与修复

使用问题代码—证据时间段—实际发生—叙事缺口—最小修复。按“补声音即可 / 重剪可修 / 关键动作缺失须重拍 / 尚未看无法判断”分类。

严重不合格不可被画质、时长、音轨数量平均掉。不承诺点击率、必爆或100%理解。没有外部观众就标同上下文自审；只完成结构测试则标结构检查。先让用户确认下一次试拍，再提交收费任务；安全拒绝不通过换词换模型规避。

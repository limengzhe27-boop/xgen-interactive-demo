# 角色发现卡：情景—姓名—钩子

依据用户2026-09-10提供并要求采纳的文案方案整理。目标是让访客想和角色聊一句，不是完整人物档案、剧情摘要或玩家身份选择。以下示例是原创宣传邀请，不是原作引文或已发送的消息。

## 三层分工

- 顶部世界情景：公开的事件、关系局面或异常，优先一行、最多两行。不写长背景，不与底部重复完整句子。
- 中部姓名：只显示角色名，视觉最醒目。不要追加年龄、性别、职业、成年标签或广告副标题。
- 底部钩子：一个最强的对话动机，优先角色口吻，其次第三人称处境，最后才是有冲突的简短身份。优先8—20字，最多两行；不是硬截断到20字。

先判断姓名与顶部是否已足够识别人物；不足时只补一个有用的身份线索。身份、年龄、职业只有自身构成剧情反差或识别需要时才融入钩子，不为档案完整而罗列。原身份数据不删除，仍供搜索与剧情使用。

## 从证据写邀请

先看公开开场、角色公开性格和已知关系，再写短句。不能借秘密制造点击、承诺未发生的结局、给陌生访客强加配偶身份，不能把别的AI示例当剧本事实。角色口吻可表现邀请、试探、幽默、亲近，不必人人威胁或交易。

例如当前第九回改编的吴月娘可用「新来的第五房，该怎样接这个礼？」；不能照搬「他给你的情话，我这里还有两份」，因为没有这项证据。李白可用「这杯酒，敬知己还是买我的沉默？」；不能声称已经写出传世名篇。

## 展示与作者控制

卡片宣传、角色身份、真实开场白是不同内容；宣传不能写入剧情历史。作者的已确认文案优先，Agent只建议，不擅改姓名或身份来曲线写宣传。没有独立宣传字段的当前生成契约，在创作讨论正文提出建议，不虚称已经写入卡片。后续新增可编辑字段时须同步生成、采纳、保存、发布和恢复链路。

手机也要能看到钩子；顶部与底部各两行截断，长姓名不能被档案挤掉。未审校内容不使用万能模板伪装成精修；缺少钩子时暂不显示身份档案作为兜底。保持首页名单、混排、搜索与点击目标不变。

## 自检

陌生用户知道什么情景、面对谁、能问哪一句吗？顶部与底部各做一件事吗？短句有公开依据吗？是否泄露答案或假装角色已经说过？检查桌面和手机样式约束、真实角色ID、搜索保留，以及未改世界状态。
